# 스킬 개선 루프 저널 (Loop Journal)

> **이 파일은 누구를 위한 것인가?**
> 일반 직원용이 아니다. **이 플러그인(ax-eval / input / output 스킬)을 *고치는* 사람**(=오너 본인)의 저널이다.
> 영상 「루프 엔지니어링」의 핵심 — *"내가 만든 스킬이 자는 동안 똑똑해진다"* — 의 뒷부분(실패노트·변경↔점수·빼기)을 닫기 위한 기록장.

---

## 루프 한 바퀴 (영상 4단계: 평가 → 제안 → 검증 → 합치기)

```
① 평가   /ax-eval 체크 로 지금 점수(baseline)를 먼저 잰다   ← 측정 없는 진화 금지
② 제안   한 번에 딱 하나만 바꾼다 (SKILL 한 줄 / 키워드 1개 / 룰 1개)
③ 검증   며칠 뒤 /ax-eval 체크 재실행 → 같은 골든셋으로 전후 점수 비교
④ 합치기 점수 올랐을 때만 유지. 안 올랐으면 revert + 아래 「실패 노트」에 1줄
```

**골든셋(고정 시험지)** = `references/ax-maturity-model.md`(5축×5단계) + 누적된 `~/ax-eval/assessments/*.json`.
시험지는 얼린다 — 측정 도중에 평가 기준(축·공식·키워드)을 같이 바꾸면 점수 비교가 무의미해진다.

## 작성 템플릿

새 사이클을 시작할 때 아래 한 줄을 해당 섹션에 추가한다. **변경 1개 = 1행.**

```
| YYYY-MM-DD | <변경 대상 파일·항목> | <한 번에 하나 가설> | <baseline 종합> | <재측정 종합> | ✅유지 / ❌버림 | <한 줄 교훈> |
```

- 종합 점수 출처: `~/ax-eval/growth-log/TIMELINE.md`의 「종합」열.
- 판정은 **종합 또는 직접 겨냥한 축**으로. (예: input 스킬 손봤으면 요청력 축으로 판정)
- "어느 정도 좋아진 것 같다"는 금지 — 숫자가 안 오르면 ❌.

## 0. 현재 baseline (비교 기준선)

> 모든 변경의 전후 비교는 **이 기준선과 같은 골든셋(고정 세션 풀)** 으로 측정해야 유효하다.

| 항목 | 값 |
|------|-----|
| 측정일 | 2026-06-10 |
| 종합 | **2.95** (⭐⭐⭐ 협업), 직전 06-02 = 3.15 (−0.20) |
| 5축 | 요청력 2.0 · 검증력 1.0 · 활용력 5.0 · 판단력 2.0 · 정리력 4.0 |
| 자산 | CLAUDE.md 172줄/9섹션 · handoff 있음 · docs 24461줄 · 슬래시 1 · 스킬 0 · rules 0 |
| **다음 개선 타깃** | **검증력 1.0** (가장 약한 축 — 한 번에 하나만 고친다면 여기부터) |

**골든셋 고정 조건** (재측정 시 동일하게 재현):
- 분석 대상 = 파일명 날짜(YYYY-MM-DD) 기준 **최근 20 세션**
- 프로젝트 = `ontology_mkt`(실작업), 2026-03~04월 옛 세션·`/init` 자동 세션 **제외**
- 정렬 = 파일 mtime(변환 시각) 아닌 **세션 실제 날짜**
- 06-10 고정 풀 = ontology_mkt 06-08 ~ 06-10 (TBox v2·D165 구현 기간)

> 첫 측정(세션 풀 미고정, 종합 2.70)은 무효 — 「2. 실패 노트」 #1 참조. 시험지 고정 후 2.95로 정정됨. 검증력 −1.0은 아티팩트가 아닌 **실제 변화**(06-08~10 순수 구현 집중 → verify_ratio 0 세션 55%).

## 1. 변경 로그 (✅ 유지된 것 = 레시피북에 적힌 것)

점수가 올라서 살아남은 변경. 이게 누적되면 그게 곧 "자는 동안 똑똑해진" 증거다.

| 날짜 | 변경대상 | 가설 (한 번에 하나) | baseline | 재측정 | 판정 | 교훈 |
|------|---------|-------------------|---------|-------|------|------|
| 2026-06-10 | `hooks/hooks.json` 검증 코치 훅 추가 | 검증 코치(요청 코치 대칭)가 verify/follow_up 발화 유도 → 검증력 1.0 ↑ | 검증력 1.0 (종합 2.95) | _(며칠 후 동일 골든셋 재측정 대기)_ | 🔄진행중 | 채점 키워드는 안 건드림(시험지 고정). 행동 유도 하네스만 변경 |

## 2. 실패 노트 (❌ 버린 것 = 오답노트)

> 영상: *"이거 해봤는데 안 됐음"이라고 한 줄 적어 놔야 한다. 안 적어두면 한 달 뒤에 똑같은 걸 또 시도한다.*

버린 변경도 **반드시 한 줄 남긴다.** 같은 막다른 길을 다시 파지 않기 위해.

| 날짜 | 시도한 변경 | 왜 좋아질 거라 봤나 | 점수 변화 | 왜 버렸나 (교훈) |
|------|-----------|------------------|----------|----------------|
| 2026-06-10 | 첫 baseline 측정 (변경 0) | loop-journal 비교 출발점 확보 | 3.15 → 2.70 (무효) | **시험지를 안 얼리고 쟀다.** 분석 세션 풀이 직전(최근 graphify/세컨드브레인)과 다른 옛 세션(2026-03~04 도서·캐릭터챗·`/init` 자동)으로 바뀜 → 정리력 -3.0·요청력 -1.0은 실제 퇴행이 아니라 측정 아티팩트. 골든셋(분석 대상 세션 풀)을 **측정 전에 고정**해야 점수 비교가 의미를 가짐. → 룰 ① 실증, 재측정으로 정정 |

## 3. 빼기 로그 (🗑 지운 것 = 군살 제거)

> 영상: *3 사이클마다 한 번은 더하는 대신 "뭘 지울까"를 고민한다. 지웠는데 점수가 안 떨어지면 공짜로 군살을 뺀 것.*

**3번 변경마다 1번**은 추가 대신 제거를 검토한다. 후보: `references/` 안 읽히는 항목 · `convert_sessions.py`의 죽은 키워드 · 안 맞게 된 룰.

## 휴먼 온 더 루프 (사람의 자리 = 루프 위, 코치)

AI(이 플러그인)는 부지런한 인턴, 사람(오너)은 사수다. **세 가지는 사람만 한다:**

1. **시험지를 소유한다** — "무엇이 잘하는 것인가"(5축 정의·공식)는 사람이 정한다. AI에게 기준까지 맡기면 자기한테 유리하게 흐린다.
2. **승인한다** — 어떤 변경을 유지·revert할지 최종 결정은 사람. 점수는 근거일 뿐.
3. **초안만 받는다** — AI는 "이런 개선 어때요?" 초안까지. 룰로 박는 건 사람.

> ⚠️ E2E QA(`scripts/verify-e2e.sh` + `/ax-eval 시작·체크·팁` 실수동 점검)는 **아직 사람이 직접** 한다 — 영상의 "마지막 한 조각". 자동화 미완.
